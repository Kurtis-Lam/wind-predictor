# 🌪️ Wind Predictor

A small PyTorch project that predicts **100 m wind (speed and direction) one hour ahead** for any point on Earth. It downloads hourly weather history, trains a bidirectional LSTM on it, and then produces prediction maps and accuracy reports.

The model looks at the **previous 96 hours** of weather (temperature, humidity, pressure, cloud cover, gusts, 10 m and 100 m wind, plus time-of-day and time-of-year signals) and predicts the 100 m wind for the **next hour**.

## 📊 About the `predictions/` folder

> **The images currently inside `predictions/` are examples of how well our model performs.** They were generated by `predict.py` using the pre-trained checkpoint and the example dataset included in this repo. They are here so you can judge the model's quality before you run anything yourself. Running `predict.py` yourself will add new images to this same folder.

There are two kinds of images:

**`period_report_YYYYMMDD.png`** (and the `2022_…`, `0.94…` variants): a three-panel chart for a time range starting on that date.
1. Actual vs. predicted wind **speed** (m/s)
2. Actual vs. predicted wind **direction** (degrees)
3. Accuracy over time (speed, direction and combined), with the average as a dashed line

Some filenames start with a number, such as `0.94period_report_20251206.png`. That prefix is the **average total accuracy** for that period, added by hand to the filename for easy comparison. For example, the 2025-12-06 report shows the predicted curves closely following the real ones, with an average total accuracy of 0.94.

**`prediction_YYYYMMDD_HHMM.png`**: a map for a **single hour**, with the predicted wind arrow, the predicted values, the actual values, and the accuracy scores.

Please don't read these as perfect. Accuracy varies from hour to hour, and the single-hour example (`prediction_20250303_0900.png`) scores noticeably lower (total 0.77) than the period averages. Sudden wind shifts are the hardest part for the model. The period reports show that dips happen, and they're a fair picture of the typical quality.

### How accuracy is calculated

Accuracy is a simple custom score, not a standard meteorological metric:

- **Speed accuracy** = `1 − |predicted − actual| / actual`
- **Direction accuracy** = `1 − (angular difference / 180°)`
- **Total accuracy** = average of the two

## 🔧 Setup

Requires Python 3.9+.

```bash
pip install requests pandas numpy torch scikit-learn pytz matplotlib cartopy
```

A GPU is used automatically for training if one is available, but the CPU works too (just slower). `cartopy` downloads coastline map data the first time it draws a map, so you need an internet connection on the first `predict` run.

---

## 1️⃣ Fetch data

```bash
python fetch_data.py
```

You'll be asked for:

| Prompt | Meaning | Default |
|---|---|---|
| Latitude | Location to fetch | `22.3193` (Hong Kong) |
| Longitude | Location to fetch | `114.1694` (Hong Kong) |
| Number of years | How much history to download | `3` |

Press Enter to accept a default. For example, to recreate the included example dataset, enter latitude `12.8308`, longitude `101.4339` and `5` years.

What happens:

- Hourly data is pulled from the [Open-Meteo historical archive API](https://open-meteo.com/) (free, no API key).
- History is only available **from 2020-07-01**, so longer requests are trimmed automatically.
- Missing values are interpolated and filled.
- East/west (`u`) and north/south (`v`) wind components are calculated at 10 m and 100 m.
- The result is saved as `data/<lat>_<lon>_<days>.txt` (a CSV file despite the `.txt` extension).

The data is stored in the **Asia/Hong_Kong** time zone, and all prediction times you type later are interpreted in that time zone too.

---

## 2️⃣ Train a model

```bash
python train.py
```

1. Enter the number of epochs (default `100`; the included example used `400`).
2. Pick one of the files from `data/` by number.

Training setup (set at the top of `train.py`):

| Setting | Value |
|---|---|
| Model | 3-layer bidirectional LSTM (128 hidden units) + fully connected head |
| Input window | 96 hours |
| Target | `u_wind_100m`, `v_wind_100m` (next hour) |
| Loss / optimizer | Huber loss / AdamW, learning rate 0.001 |
| Batch size | 128 |
| Split | First 80% of the timeline for training, last 20% for validation |
| Early stopping | Stops after 30 epochs without improvement |

Each run creates a new folder named like `model_<timestamp>_<data file name>_v2/` containing:

- `best_model.pth`: the checkpoint with the lowest validation loss (this is what `predict.py` uses)
- `latest_checkpoint.pth`: a snapshot saved every 10 epochs

The checkpoint also stores the feature scaling values and settings, so `predict.py` can reload it with no extra configuration.

---

## 3️⃣ Make predictions

```bash
python predict.py
```

1. Choose a model folder (any folder starting with `model_` next to the script, including the included example).
2. Choose a data file from `data/`.
3. Type one of the commands:

### `predict`: a single hour

Enter a time such as `2025-03-03 09:00`. The script predicts the wind for that hour using the 96 hours before it, then draws a map with the predicted arrow, predicted vs. actual values, and the accuracy. It is saved as `predictions/prediction_YYYYMMDD_HHMM.png`.

### `predict_period`: a range of hours

Enter a start and end time (for example `2025-12-06 00:00` and `2025-12-12 00:00`). The script predicts every hour in the range, prints average speed/direction/total accuracy to the console, and saves the three-panel chart as `predictions/period_report_YYYYMMDD.png`.

### `quit`

Exits the program.

**Tips**

- Every time you ask for needs the **96 hours before it** to exist in the data file. If it doesn't, you'll see a message showing the available date range.
- If the requested time is after your data ends (but the previous 96 hours exist), you still get a prediction, just without the "actual" values and accuracy.
- `predict_period` overwrites a report with the same start date. Rename any you want to keep.

---

## ⚠️ Good to know

- **This is a one-step-ahead nowcast.** The model uses *real observed* weather from the past 96 hours to predict the next hour. It is not a multi-day forecast.
- **Models are location-specific.** A model trained on one location's data is intended for that location. Train a new one for a new place.
- **If you change the model settings** (hidden size, layers, sequence length, dropout) in `train.py`, make sure `predict.py` matches. Its sequence length (`96`) and dropout values are written directly into the script.
